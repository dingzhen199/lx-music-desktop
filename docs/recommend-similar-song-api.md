# 探索推荐：封装平台相似歌曲接口（未来实现）

> 状态：已确认方向，未实现。本文档仅为后续开发留底。

## 背景

探索/AI 推荐的召回（`src/renderer/core/recommend/recall.ts`）当前只有三个来源：

- 同艺人歌曲搜索（top 10）；
- LLM 分析产出的语义关键词搜索（≤4 条，每条每源 top 10）；
- 本地用户收藏歌单池。

其中歌曲搜索结果是平台热度排序，不是语义匹配，是候选池质量的主要瓶颈。

## 方向

网易（wy）、QQ（tx）平台的客户端存在单曲级「相似歌曲」接口，按种子歌曲直接返回相似曲目，质量预期高于关键词搜索的热度榜。lx 的 musicSdk（`src/renderer/utils/musicSdk/`）目前未封装该类接口，需要自行封装后作为新召回源接入。

## 接入点（实现时的预期路径）

1. 在 `musicSdk/wy`、`musicSdk/tx` 下新增相似歌曲接口封装（结构参考现有 `musicSearch`、`songList`），按源降级，单源失败不影响整体。
2. `recall.ts` 新增召回源 kind（如 `similar`），以锚点歌曲为种子拉取相似曲目，建议感知距离与同艺人之上的语义档同级或略近。
3. 候选汇总后仍走 `candidatePool.buildCandidatePool` 既有管线（id 去重 → 锚点排除 → 红心排除 → 语言门控 → 同曲去重），不新增守门逻辑。

## 前置调查

- 具体接口端点、请求参数与响应结构需从平台 Web/App 实际流量核实，本文档不写死任何未经核实的端点。
- 确认接口返回是否包含可用于 `toNewMusicInfo` 归一化的必要字段（songmid/hash 等可播放 id，无 id 条目按 `rawHasId` 现有规则丢弃）。

## 风险与约束

- 非公开接口无稳定性承诺，字段可能漂移；封装需带兜底，接口失效时静默降级回现有召回源。
- 本机已观察到各源存在限流，新增调用需评估触发限流的概率，仅在探索会话发起时调用，不做批量预取。
- 需自行评估各平台使用条款的合规风险。
