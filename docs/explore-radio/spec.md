# 探索电台 Spec（to-spec：只汇总已确认决定）

来源：2026-09-12 grill-with-docs 三轮裁决（Q1–Q14）+ B7 审核补裁（文档修订于 2026-09-13），决策全文账本见下文 D1–D15；状态机与成本立场的"为什么"见 `docs/adr/0001-explore-radio-state-machine.md`；统一词汇见仓库根 `CONTEXT.md`。

## 目标

把现有"从此歌出发"手动会话演进为**探索电台**：电台开启期间跟随切歌自动重锚开台，推荐持续追加稍后播放队尾；一句话约束、探索距离、far/good 反馈在 run 内持续生效并可随时调整偏好；排序分 AI/本地两档，无 Key 可开台。

## 非目标（明确不做）

- 相似歌曲列表 / 相似模式（D1）
- 跨会话口味档案、任何形式的红心正偏好（D4，红心仅排除）
- 服务端遥测、推荐数据上报（D10）
- LLM 调用额度闸（D9）
- 候选预览音频特征、外部相似艺人接口（D5）
- tags 透传（B1 事实核查：`toNewMusicInfo` 归一化不含 tags/genre 字段，无源数据）

## 边界

- 改动集中在 `src/renderer/core/recommend/`（session-core/session/engine/recall）、设置项（新增 `recommend.radio`）、播放栏开关、设置页开关、Explore 页入口语义对齐、`src/lang` 四语言 i18n、`src/renderer/utils/data.ts`（指标落盘读写对）。
- T-B0 移植语义文件保持只读：`judgment.ts`、`prompts.ts`、`gates.ts` 语义不改（低置信拦截在 engine 的 aiRank 内实现）。
- 电台不强占当前播放；只操作稍后播放队列，且只清理本 run 入队项，不动用户手动排队的歌。
- 机制性管道文件（如 DATA_KEYS 常量、IPC 注册）属实现必需，不计入语义边界。

## 模块设计（codebase-design 词汇）

- **深模块：电台状态机（session-core）**。接口收敛为一组纯转移函数：建/收 run、切歌判定 `decideOnSongChange(状态, 新歌, 队列快照) → { kind: 'on-path-refill' | 'reanchor' | 'ignore', 需清理的推荐 id }`、反馈、距离/约束更新、`analysisStale(会话, 新约束)` 谓词、指标事件归并（纯 reducer）。实现里藏住：run 继承、清场范围计算、批次快照、同曲判定。接口即测试面，vitest 直测。
- **适配器：session.ts**。订阅播放事件、执行队列增删、调 `exploreOnce`、管理定时器与代际；不含判定逻辑。约束作废通过"不传 reuseAnalysis"实现，engine 接口不变。
- **适配器：data.ts 指标读写**。新增一对 get/set，存储单个 JSON；由 session 编排层在事件点写入。

## Test Seams

- session-core 纯函数全部经 vitest（沿用仓库既有模式：不启动框架）。
- engine.ts 依赖播放器状态/IPC，无法被 vitest 加载：低置信判定须抽离为独立纯函数模块（参照 vocalGate.ts 先例），engine 引用；纯函数按近/中/远三档半径补 vitest。
- session.ts / recall.ts / 播放器 IPC 为集成层：vitest 不覆盖，验证 = 类型检查 + lint + 全量构建 + 手动冒烟脚本。

## 验收标准（AC）

- AC1（跟歌重锚）：开电台后切到任意非推荐歌曲，一个计划周期内以新歌为锚点完成清场 + 新计划入队尾；手动排队的歌不受影响。（手动冒烟）
- AC2（队尾）：电台所有批次追加队尾；队列已有用户歌曲时插在其后。（冒烟 + session-core 单测）
- AC3（分析作废）：run 内修改一句话约束后，下一次计划以新约束重新分析（路径批次快照的 instruction 变化且召回查询集变化可证）。（冒烟 + 单测 analysisStale）
- AC4（run 沿用）：自动重锚继承 instruction/radius/正负面艺人；收台后重开全部重置。（单测）
- AC5（无 Key 分档）：未配 API Key 可开台，engine=local，页面展示本地模式。（冒烟）
- AC6（低置信拦截）：confidence=low 候选在全半径被拦截。（单测）
- AC7（指标）：四个计数器随事件增长并落盘，重启后可读。（dev hook 读取验证）
- AC8（回归）：既有 vitest 全绿 + 新增用例全绿；类型检查、lint、全量构建通过。
- AC9（收台语义）：切歌判定中重锚分支优先于任何队列清空语义；同一 run 连续三次计划最终失败触发收台（initial/refill 均计入，成功清零）。（单测）
- AC10（重启恢复）：电台开关持久为开时，应用重启后的首次播放事件自动以当前歌开台。（冒烟）

## 剩余风险

- **LLM 成本无闸**（D8，自担）：连播自己曲库时按歌烧调用链。
- **冷歌幻觉**：候选判定依赖 LLM 先验，AC6 只是缓解不是根治。
- **空结果频次上升**：低置信全拦 + 换道过滤叠加，空态文案已有分级，需冒烟确认体验可接受。
- **集成层只能靠手测**：切歌竞争（电台计划中用户又切歌）依赖既有 epoch 代际回滚机制，冒烟需重点覆盖。
- **切歌风暴**：快速连切触发连续重锚；重锚计划沿用与续补同量级的防抖（约 1.2 秒）吸抖。
- **指标时长口径**：30 秒跳过判定以 play/pause 事件累计的实际播放秒数为准，不取切歌墙钟间隙（墙钟口径会把暂停误计为播放时长）；进度 seek 造成的少量偏差接受。

## B4 结论（prototype 判定）

不做一次性原型。状态模型是既有 session-core 的延伸（run 层为纯数据提升 + 一个切歌判定函数），交互只有一个开关，可行性由现有引擎多次验证；没有"没底"到需要原型回答的问题。
