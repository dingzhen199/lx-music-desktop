# 本地用户画像：行为信号增量累计与红心证据地位

**Status**: accepted（2026-09-14，两轮 grill-with-docs 裁决 Q1–Q10）

推荐域引入**本地用户画像**：收藏（加入「我喜欢」）、听完（自然播放达到曲目时长的 90%）、推荐曲被 30 秒内切走，三类行为信号在本地增量累计为艺人计数底座（滚动事件缓冲 + 截断），有 API Key 时再按增量阈值异步生成一段散文摘要；画像同时作用于 AI 档（摘要拼入排序指令）与本地档（艺人加分/降分）。红心歌的地位从「仅排除」改为「排除 + 画像证据」：已收藏的歌仍不重新进入候选（不构成推荐结果），但收藏动作构成画像的正向证据。行为信号中对象为本台推荐曲的子集（背书）即时作用于当前 run（方向层面等同 good，触发一次续补）；跳过的负向证据只进画像降权，不进入 run 级 negativeArtists。

本决定**取代**探索电台 spec 的 D4（不做跨会话口味持久）及非目标中「任何形式的红心正偏好」条款：画像正是跨会话的口味持久，从否决项转为正式能力。立场反转的理由：D4 当时的对立面是"设置级持久口味档案，无限拟合过去"，本次落地的形态是**行为证据的增量记账**——它只调整候选倾向性，不动摇"此刻状态优先"的探索语义（锚点、距离、约束、守门全部照旧）。

## Considered Options

- **增量累计记账（采纳）** vs 每次计划全量重读收藏列表重算画像（否决：收藏越多越慢，"越用越慢"是本立项的直接动机）。
- **本地计数底座 + 有 Key 时 LLM 散文摘要（采纳）** vs 纯 LLM 画像（否决：无 Key 用户残缺，违背"本地引擎是完整可用降级档"）vs 纯本地计数（否决：风格语义表达弱，摘要让 AI 档能读到"气质"而非仅艺人名单）。
- **背书即时作用于 run（采纳）** vs 隐式信号一律只进长期画像（否决：用户明确要求收藏推荐歌后下一批可被感知）。
- **跳过只进画像降权（采纳）** vs 即时进 negativeArtists（否决：切歌原因多样，误伤成本高）vs 完全不做负向（否决："这个艺人的推荐总被跳"是有价值的长期证据）。
- **红心排除保留（采纳）** vs 红心歌可作候选（否决：探索语义是发现新声音，不推荐用户已有的歌）。

## Consequences

- 画像事件来源不限于电台：收藏任意歌、听完任意歌都进画像；只有负向跳过限定为推荐曲（非推荐曲的跳过是用户自选行为，不作推荐质量证据）。
- 画像摘要的 LLM 成本延续"自用场景无额度闸"立场：阈值触发（每累计 20 个新正向事件）、fire-and-forget、失败保留旧摘要。
- 背书与显式反馈可同曲叠加（先收藏又按 far 时正负艺人同存）：与既有"显式 far/good 同曲"行为一致，接受现状。
- 画像数据只在本地 `data.json`，本期不提供 UI 管理入口；清除路径 = 删除数据文件对应键。
- 听完判定的时长快照锚定 `playerLoadeddata` 事件（切歌点 `maxPlayTime` 已被确定性清零，不可作快照点）；元数据加载前被切走的曲目保守不判定，宁缺毋滥。
- 依赖方向恒为 session → profile 单向：收藏信号经 `window.app_event` 事件桥、推荐曲跳过由 session 判定后回注，profile 不 import session；取消收藏不回扣计数、整单恢复/迁移不产生信号（B7 审核补裁）。
- 画像摘要与 instruction 的 `stateWords` 机器解析面（排除词/语言硬门/器乐门/格式门）永久隔离：摘要走独立的 `profileSummary` 通道只进 LLM 排序提示词文本——口味散文几乎必然含"器乐/轻音乐"等体裁词，走 instruction 注入会翻转器乐硬门、滤空人声候选乃至连续计划失败收台（B7-R3 补裁）。
